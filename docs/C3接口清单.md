# C3 建造核心接口清单

> C2 骨架（306ca16）为 C3 预留的全部接口、待办债与红线约定。
> C3 范围（GDD §7）：网格放置/拆除、资源节点、采集者智能体（A*/流场寻路）、生产链数据驱动。

## 1. 直接可用的接口

### BuildGrid（`com.mog.game.BuildGrid`，静态工具）

| API | 说明 |
|---|---|
| `CELLS=32` / `CELL_SIZE=2.0f` / `HALF_EXTENT=32` | 网格常量：64m×64m 活动区 |
| `inBounds(x, z)` | 世界坐标是否落在建造区 |
| `worldToCell(w)` | 世界坐标 → 格索引（floor + 钳制 [0,31]） |
| `cellToWorld(cell)` | 格索引 → 格中心世界坐标（-31, -29, …, +31） |
| `snap(w)` | 世界坐标吸附到最近格中心 |

**C3 待补**：占位 bitmap（32×32 布尔/位掩码，记录格子占用与建筑 ID）——C2 刻意未做，
放置/拆除逻辑落地时在 BuildGrid 之上建独立的 OccupancyGrid（数据与逻辑分离）。

### TerrainBuilder（静态工具）

- `heightAt(x, z, heightScale, seed)`：纯函数高度查询（无状态、无 Random 实例），
  地形/网格线/建筑落位三方一致性靠它。C3 建筑落位、采集者贴地行走都用此查询。
- `build(cells, cellSize, heightScale, seed)`：整块地形网格（C3 一般不需要重建）。
- SurfaceScene 的地形种子 = `session.getSim().getSeed() * 31 + 7`（同乐章内稳定）。

### RtsCameraRig（拾取预留）

- `getFocus()` / `getHeight()` / `getYaw()`：C3 屏幕→地面拾取时，由焦点+高度+固定
  俯角 45° 可解析求射线；或直接走 `Camera.getForward` + `physics.Ray` 与地面平面求交。
- 焦点钳制 ±40（`MAX_FOCUS`），拾取坐标不会跑出建造区太远，但仍应过 `inBounds`。

### CosmosSession（只读消费 + 时间控制）

- 纪元/宿主星/历法/终局：`getCurrentEpoch()` / `getHostTracker()` / `getSim()` /
  `isRunEnded()` / `getEnding()`——C3 生产衰减、灾变判定从这里读，**不得另算**。
- 时间控制已由 SurfaceScene.handleInput 接线（空格/±）；C3 若加 UI 按钮，调用同一会话 API。
- 会话是 Game 级唯一真源：任何系统不得持有其可变内部状态跨帧缓存（纪元节流字段除外）。

### SurfaceScene 的 eventBus 入参

- 构造入参 `EventBus` 当前**只存不用**——为 C3 发布建造/拆除/结算事件预留。
- **红线：场景不得订阅 EventBus**（EventBus 只有 `clear()` 无退订，场景实例随 Tab
  切换销毁重建，订阅会跨场景泄漏）。C3 事件订阅一律放 Game 级（`wireEvents`）。

## 2. 渲染与视觉债

| 债 | 现状 | C3 动作 |
|---|---|---|
| IBL 与纪元色 | `environment.build(Light.defaults())` 中性光，lit 管线不采样 IBL | 建筑上 PBR 材质时做异步双 Environment 轮换或按纪元预烘焙套 |
| 占位方盒 | 共享 `Shapes.createCube()`，4 个手工落位实体 | 替换为真实建筑模型/程序化低模；注意 ownedMeshes 释放约定（共享 Mesh 只释放一次） |
| 网格线高亮 | GridRenderer 静态一次上传，α 0.28/0.56 两档 | 放置预览需"当前格高亮"——建议独立小 VBO（1 格 4 段线）动态更新，勿改静态大缓冲 |
| 阴影参数 | SURFACE 用 `setShadowParams(90,48,1,220)`，复位集中在 `Game.applySlotRenderState` | 建筑增高后若阴影截断，调 far/extent 也在 applySlotRenderState 改，场景不各自为政 |

## 3. 流程约定（踩过的坑）

- **HUD 字符烘焙**：新增 HUD 文案必须同步 `Game.HUD_CJK_CHARS` 与
  `C:\tmp\smoke\CharsetCheck.java`（仓库外冒烟脚本），否则缺字显示空白。
  跑 `CharsetCheck` 必须 PASS 再提交。
- **GL 状态清单**：新 overlay 渲染器学 GridRenderer——类注释列全状态
  （混合模式/深度写/背面剔除的开关与恢复），勿抄 TrailRenderer 的加色混合。
- **零每帧分配**：Vector3f scratch 字段复用；Light 经活引用就地改写。
- **实体类不放逻辑**（全局规则）：建造规则进工具类/系统类，组件纯数据。
- **无头验证优先**：C3 放置/寻路/生产链逻辑全部先写纯 Java 断言测试
  （参考 `C:\tmp\smoke\SurfaceLogicTest.java` 模式），GL 部分再真机跑测。
